# Nested AGENTS.md Index For Agronomist Guidance

This index explains how the agronomist `AGENTS.md` tree is organized and how future nested workflow profiles should be added. The tree is a portable instruction structure, not an automatic dispatcher. Tools may load root guidance, nearest guidance, a concatenated directory chain, or only the file that a user explicitly opens. Referenced documents and sibling profiles are discovery aids, not guaranteed loaded instructions.

Use the public root profile first, then consult the most specific existing child profile when it clearly matches the task. If a future leaf path listed below does not exist yet, treat it as planned routing guidance only and stay with the closest existing profile.

## Portability Model

- Every profile must make sense when read alone, because some tools may not load parent files or referenced documents.
- Parent files should stay compact. Put deeper task mechanics in workflow leaves only when those mechanics change the work.
- `catalog.json` remains top-level and flat. Nested paths are discoverable through this index and the root routing text, not through nested catalog entries.
- The tree does not auto-load child profiles, auto-dispatch tasks, call sub-agents, or promise that linked files are in context.
- Route by the grower's decision and evidence artifact, not by the most scientific-sounding taxonomy label.

## Depth Budget

Use this depth budget for agronomist guidance.

| Level | Meaning | Allowed content |
|---|---|---|
| L0 | Repository conventions | Repository usage, catalog behavior, symlink behavior, validation, and shared public documentation rules. |
| L1 | Profession root | `scientific-agents/agronomist/AGENTS.md`, shared agronomist role, boundaries, principles, and top routing caveats. |
| L2 | Anchor | One of the 16 current child directories that represents a stable agronomy domain or task family. |
| L3 | Workflow | A concrete task flow under an anchor, such as scouting triage, trial design, or recommendation writing. |
| L4 | Subworkflow | A narrower phase inside a workflow that changes sequencing, checks, or outputs. |
| L5 | Situation or artifact | A specific field situation, decision artifact, or evidence artifact that needs distinct instructions. |
| L6 | Edge-case or localization template | Rare but stable edge cases, local calibration templates, or regulatory/source calibration contexts. |

### Material-Specificity Gate

Create a deeper profile only when it materially changes at least one of agent behavior, required inputs, expected outputs, caveats, or workflow phase. Do not create a child profile for taxonomy alone, crop names alone, bibliography expansion, or a more specific title that keeps the same instructions as its parent.

Before adding a new level, ask whether the child has different required inputs, a different decision artifact, a unique caveat or handoff rule, a changed workflow order, or enough standalone value for nearest-only tool behavior. If not, keep the guidance in the parent.

## Source Category Guidance

Profiles should name source categories without long URL lists. Prefer current public authority such as land-grant extension, national extension systems, NRCS and conservation practice standards, pesticide labels and regulator systems, certified adviser standards, SARE and farmer-research networks, peer-reviewed applied agronomy, and locally calibrated crop guides. Reject unsupported sources, vendor marketing, SEO summaries, anonymous advice, AI summaries, placeholders, testimonials, and single-site dealer plots as primary authority.

## Line-Budget Policy

Default `AGENTS.md` length is 40 to 80 lines. That range keeps parent and anchor guidance cheap to load while leaving room for role, source basis, inputs, outputs, decision rules, boundaries, and caveats. Exceptions must be justified in this index before the profile grows beyond the default, usually because standalone safety context, regulatory caveats, or multi-phase workflow checks are essential.

Current exception policy: L3 to L6 workflow leaves may exceed 80 lines only when the added lines materially protect standalone use. Root and L2 anchors should stay concise unless a future review records a specific public rationale here.

## Standalone Leaf Rule

Every L3 to L6 leaf must include enough critical context for a user or tool that sees only that file. A leaf should state its parent anchor, when to use it, when not to use it, required inputs, missing-input handling, expected output, specific decision checks, boundaries, handoffs, local calibration caveats, and the reminder that referenced docs are discovery aids rather than guaranteed loaded instructions.

## No Catalog Nesting Decision

Nested agronomist paths are intentionally excluded from `catalog.json`. The catalog stays a flat list of top-level public profiles. This index and the root agronomist profile are the discovery layer for nested paths, so adding a workflow leaf should update discovery text here rather than creating nested catalog entries.

## Justification For Any Future Exceptions

Record future line-budget exceptions here only when a profile must exceed the default to remain safe and standalone. Acceptable reasons include legal or label caveats, multi-phase trial quality checks, source-calibration steps, or critical handoff rules that would be unsafe to omit.
